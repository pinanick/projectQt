# CyberLab · минимальная демонстрационная версия

Учебное приложение с простым стандартным интерфейсом на **Python, PyQt6 и SQLite3**, моделирующее базовый анализ событий информационной безопасности. 

## Что уже работает

- **Обзор:** число событий, ошибок входа и найденных инцидентов.
- **Журнал:** таблица событий и поиск по IP/пользователю с фильтром типов.
- **Генератор:** создание вымышленных событий входа, в том числе серии ошибок.
- **Анализатор:** поиск 5 и более неудачных входов с одного IP за 60 секунд.
- **Инциденты:** просмотр тревог, изменение статуса и сохранение комментария.
- **SQLite:** автоматическое создание базы и сохранение данных между запусками.

## Демонстрация (1–2 минуты)

1. Запустить `main.py`. При первом запуске создаются 48 тестовых событий.
2. Открыть вкладку **События** и показать журнал и фильтр.
3. Нажать **Анализировать**. Появится хотя бы одна тревога.
4. Открыть инцидент, поменять статус и сохранить комментарий.
5. Перезапустить приложение: статус и события сохраняются в SQLite.
6. Кнопка **Сгенерировать события** добавляет ещё одну порцию учебных логов.

## Архитектура

```text
main.py                    точка входа, создание окна и БД
config.py                  константы и пути
core/
  event_generator.py       генератор искусственных логов
  event_analyzer.py        алгоритм скользящего окна
database/
  db_manager.py            подключение SQLite и создание таблиц
  repository.py            SQL-запросы, чтение и изменение данных
ui/
  main_window.py           главное окно, кнопки, QTabWidget
  common.py                общие элементы интерфейса
  pages/
    dashboard_page.py      обзор
    events_page.py         журнал событий
    incidents_page.py      просмотр и изменение инцидентов
```

## База данных

| Таблица | Что хранится |
|---|---|
| `events` | ID, дата/время, пользователь, IP, тип события |
| `incidents` | ID, IP, пользователь, первое событие серии, время начала/конца, число ошибок, статус и комментарий |

`incidents.first_event_id` связан с `events.id`. Уникальность пары `(ip, first_event_id)` предотвращает запись одной и той же серии при повторном анализе.

## Алгоритм

`detect_failed_logins()` объединяет события с ошибками входа по IP, сортирует по времени и использует очередь `deque`. Из неё удаляются события старше 60 секунд. Если накопилось 5 ошибок, создаётся кандидат на инцидент. Сам анализатор не работает с базой: найденные записи сохраняет `Repository`.
